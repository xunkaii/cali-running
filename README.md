# 다시, 러닝 — 기간별 기록과 러닝 레벨

GitHub Pages용 한국어 정적 웹앱. 서버·계정·외부 API·프레임워크가 필요 없습니다. NRC 캡처 자동 입력을 처음 쓸 때만 OCR 엔진을 jsDelivr에서 내려받습니다.

## 사용법

화면 순서: ① 기간 선택 → ② 누적 총거리(가장 큰 숫자) → ③ 기간 거리·러닝 횟수 → ④ 누적 종합 통계 6개(3열 × 2행) → ⑤ 기간별 거리 막대그래프 → ⑥ 월별 러닝 달력 → ⑦ 누적 러닝 레벨.

- 상단 주/월/년/전체 버튼으로 조회합니다. 기본값은 월입니다.
- 상단 화살표는 조회 기간을 이동합니다. 현재 버튼은 한국 날짜 기준 현재 기간으로 돌아갑니다. 현재 달에서 주 모드로 바꾸면 오늘이 속한 주가 열립니다.
- **가장 큰 거리와 6개 통계는 선택 기간 종료일까지의 누적**입니다. 기록 없는 달에도 과거 기록은 포함됩니다.
- 회색 상자(기간 거리·횟수)와 막대그래프는 그 기간에 새로 달린 거리만 표시합니다. 그래프는 주=요일별, 월=일별, 년=월별, 전체=연도별이며, 거리 표 보기에서 정확한 수치를 읽을 수 있습니다.
- 달력은 모든 모드에서 사용할 수 있습니다. 월 모드에서는 달력 이동과 조회 월이 함께 이동합니다. 다른 모드에서 달력 화살표는 입력할 월만 이동합니다.
- 날짜를 누르면 하단 시트가 열립니다. 날짜·원본 거리·시간을 입력해 저장하고, 같은 날 여러 러닝을 추가하거나 개별 수정·삭제할 수 있습니다. 같은 날짜에 NRC 거리와 시간(초 단위)까지 같은 기록이 이미 있으면 같은 캡처를 두 번 올렸을 수 있다고 묻고, "확인"을 누르면 그대로 저장합니다. 하루 두 번 러닝처럼 거리나 시간이 다르면 묻지 않습니다.
- 입력 창의 **NRC 캡처로 자동 입력**에서 NRC 러닝 상세 화면 캡처를 고르면 날짜·거리·시간·심박수·케이던스·칼로리·고도를 채웁니다. 자동 저장하지 않으므로 색칠된 칸의 값을 확인한 뒤 저장하세요.
- 맨 아래 레벨 카드를 누르면 레벨 목록, 전체 누적 거리, 다음 레벨까지 남은 거리와 진행률이 열립니다.
- 정보 버튼에서 원본 누적 거리, 보정 한계, JSON 백업·복원을 확인합니다.

## 세 가지 계산 기준

1. 기간별 거리: 선택 기간 안의 기록만 합산합니다.
2. 종료일 기준 누적: 선택한 주의 일요일, 달의 마지막 날, 해의 12월 31일까지 합산합니다. 전체 모드는 모든 기록입니다.
3. 레벨: 조회 기간과 관계없이 저장된 모든 기록의 누적 거리입니다.

한국 오늘 날짜는 `Asia/Seoul`로 구합니다. 주간은 월요일~일요일이며 날짜 연산은 UTC 기반의 날짜 문자열 연산으로 처리하여 기기 시간대·서머타임 영향을 피합니다.

모든 거리 집계는 `원본 거리 × 기록별 적용 계수`의 반올림 전 값으로 계산합니다. 큰 거리, 원본 거리, 시간, 칼로리, 고도, 평균 페이스·심박수·케이던스는 종료일 기준 누적을 사용합니다. 페이스는 총 시간/총 보정 추정 거리, 심박수·케이던스는 해당 값이 있는 기록의 시간 가중 평균입니다. 없는 값은 0으로 넣지 않습니다. 거리 소수 둘째 자리·페이스 초 단위 반올림은 표시할 때만 수행합니다.

## 초기 기록과 누적 예시

2026-10-09: 원본 2.71km, 28:24, 122kcal, 8m, 평균 심박수 149bpm, 최대 163bpm, 케이던스 163spm.

2026-10-11: 원본 2.65km, 25:27, 126kcal, 7m, 평균 심박수 172bpm, 최대 181bpm, 케이던스 150spm.

| 조회 | 기간 거리 | 종료일 누적 | 기간 횟수 |
|---|---:|---:|---:|
| 2026년 9월 | 0.00km | 0.00km | 0 |
| 2026년 10월 | 9.00km | 9.00km | 2 |
| 2026년 11월 | 0.00km | 9.00km | 0 |
| 2026년 12월 | 0.00km | 9.00km | 0 |
| 2027년 1월 | 0.00km | 9.00km | 0 |

10월 이후 누적 통계: 53:51, 248kcal, 15m, 5′59″/km, 약 160bpm, 약 157spm. 레벨은 옐로우이며 오렌지까지 약 41.00km입니다. 11월에 보정 추정 5km를 추가하면 10월 종료 누적은 9.00km, 11월 종료 누적은 14.00km입니다.

## 러닝 레벨

`model.js`의 `LEVELS`에서 구간과 색상을 관리합니다.

| 레벨 | 전체 거리 구간 |
|---|---|
| 옐로우 | 0 이상, 50km 미만 |
| 오렌지 | 50 이상, 250km 미만 |
| 그린 | 250 이상, 1,000km 미만 |
| 블루 | 1,000 이상, 2,500km 미만 |
| 퍼플 | 2,500km 이상 |

진행률은 현재 단계의 시작~다음 단계 시작 사이의 비율이며, 다음 단계에 도달하기 전에는 최대 99%로 표시합니다. 경계 비교에는 기록 합산의 부동소수점 오차(예: 49.99999999999999)만 흡수하는 1e-9km 허용오차를 둡니다. 퍼플은 최고 단계이며 남은 거리를 표시하지 않습니다. 색상은 기간 선택·그래프 막대·달력 러닝 날짜·레벨 카드·진행 막대에 적용됩니다. 가장 큰 누적 총거리 숫자는 레벨과 관계없이 검정(`--ink`, #111)입니다. 글자는 색상별로 더 어두운 색조를 사용해 가독성을 높였습니다. 로고와 그래픽은 Nike 자산을 사용하지 않습니다.

## NRC 캡처 자동 입력

`ocr.js`가 담당합니다. 캡처를 고르면 브라우저 안에서 [Tesseract.js](https://github.com/naptha/tesseract.js) 7.0.0(한국어+영어)으로 글자를 읽습니다. 이미지는 어디에도 업로드되지 않습니다. 처음 한 번은 엔진과 언어 데이터 약 6MB를 jsDelivr에서 내려받고, 이후에는 브라우저에 캐시됩니다. 인터넷이 없으면 이 기능만 쓸 수 없고 나머지 기능은 그대로 동작합니다.

1. 이미지를 회색조로 바꾸고 다크 모드 캡처는 반전합니다.
2. 화면 전체를 읽은 뒤 라벨(거리·킬로미터, 평균 페이스, 러닝 시간, 칼로리(근사치), 평균 케이던스, 고도 상승, 평균 심박수, 최대 심박수)과 숫자를 짝짓습니다. NRC 상세 목록처럼 라벨 왼쪽·값 오른쪽인 화면과, 값 아래에 라벨이 있는 요약 화면 모두 읽습니다. 영어 NRC 라벨도 인식합니다.
3. 짝지은 숫자 칸만 잘라 크기를 맞춘 뒤 숫자 전용으로 한 번 더 읽습니다. 큰 거리 숫자(2.71 → 2./1), 단위가 붙은 값(2.71km → 2.711, 8 m → 807) 오판독을 바로잡습니다. 잘라낼 때 옆 단어(단위 m 등)와는 글자 높이의 1/4만큼 띄웁니다.
4. 날짜는 `2026. 10. 9.`, `2026년 10월 9일`, `10월 9일`, `26. 10. 9.`, `10/9/26`, `Oct 9, 2026` 형식을 읽습니다. 날짜를 찾으면 날짜 칸도 바꾸고, 캡처에 날짜가 없으면(상세 목록을 스크롤해 날짜가 가려진 경우 등) 달력에서 선택한 날짜를 그대로 두고 그렇다고 안내합니다.

평균 페이스·최고 페이스·경과 시간·고도 하강은 다른 칸에 잘못 들어가지 않도록 읽기만 하고 입력하지 않습니다(시간은 러닝 시간, 보정 페이스는 거리·시간으로 계산). 마일 기록은 km로 바꿉니다. 범위를 벗어난 값(심박수 30~250 밖 등)과 평균보다 낮은 최대 심박수는 채우지 않습니다. 캡처에 최대 심박수가 없으면 비워 둡니다. 결과는 OCR 추정이므로 저장 전에 반드시 확인하세요.

## 저장과 호환성

localStorage 키 `running-correction.records.v1`과 `{schemaVersion:1, initialized:true, records:[...]}` 구조를 유지합니다. 누적 결과나 레벨은 저장하지 않고 기록에서 매번 계산하므로 중복 합산되지 않습니다.

각 기록의 id, date, distance, durationSeconds, appliedFactor, correctedDistance, correctedPace, averageHeartRate, maxHeartRate, cadence, calories, elevationGain, note를 유지합니다. 기본 계수 `4.55 / 2.71`은 새 기록에만 적용하며, 수정 시 기존 기록의 적용 계수를 유지합니다.

저장 키가 없을 때만 고유 ID 두 개의 초기 기록을 등록합니다. 삭제된 초기 기록을 다시 만들지 않습니다. 기존 초기 ID에서 고도 속성 자체가 없을 때만 8m/7m를 보완하며, null·0·사용자 수정값은 유지합니다.

JSON 복원은 형식·날짜·숫자·계산값·파일 내 중복 ID를 검증하고 한 번에 병합합니다. 동일 ID는 현재 기록을 유지하고 건너뜁니다. 최대 10,000개 기록, 메모 2,000자. 저장소 손상이나 용량 부족 시 기존 데이터를 덮어쓰지 않으며 오류를 표시합니다. 다른 탭의 변경이 감지되면 새로고침하도록 안내합니다.

브라우저 데이터 삭제, 비공개 탐색 종료, 다른 기기로 이동하면 데이터가 자동 이전되지 않습니다. JSON 백업을 보관하세요.

## 보정의 한계

결과는 실제 거리를 확정하지 않는 추정치입니다. 2026-10-09 동일 경로의 두 기록을 비교한 임시 비율이며 비교 거리 4.55km 역시 독립 검증되지 않았습니다. 오차율이 일정하다는 가정이며 GPS 복원·기기 진단·NRC 기록 변경 기능은 없습니다.

## GitHub Pages 배포

1. 공개 GitHub 저장소를 만들거나 기존 저장소를 엽니다.
2. `index.html`, `style.css`, `model.js`, `ocr.js`, `app.js`를 같은 최상위 폴더에 함께 업로드합니다. `fixtures/`와 `test.cjs`는 테스트용이라 올리지 않아도 됩니다.
3. Settings → Pages → Deploy from a branch → main → /(root) → Save.
4. 배포 완료 후 Pages에 표시되는 주소를 엽니다.

빌드나 패키지 설치가 필요 없습니다. 상대 경로를 사용하므로 프로젝트 하위 URL에서도 동작합니다.

배포 주소: <https://xunkaii.github.io/running/> (저장소 <https://github.com/xunkaii/running>, main 브랜치 루트). `.nojekyll`로 Jekyll 변환을 건너뜁니다. `test.cjs`와 `fixtures/`는 `.gitignore`로 제외해 이 폴더에만 둡니다. 파일을 고친 뒤에는 이 폴더에서 `git add -A`, `git commit -m "내용"`, `git push`를 실행하면 1~2분 뒤 사이트에 반영됩니다.

## 검증

계산·입력 검증, 초기 데이터 유지, 기록 추가·수정·삭제, 재로딩, JSON 왕복과 중복 처리, 가중 평균, 초기 고도 보완, 기간별 버킷, 한국 날짜 자정, 연말 주간 경계, 이전/다음 달·다음 해 누적 유지, 11월 5km 추가/삭제, 모든 레벨 경계, 진행률, 조회 시 데이터 불변, UI 이벤트를 검증합니다.

UI 테스트는 한국 날짜를 2026-10-12로 고정하고, 같은 저장소로 앱을 다시 실행해 새로고침을 재현합니다. 요구사항별 회귀 테스트(`요구1`~`요구8`)는 실제 버튼·저장·삭제 이벤트로 다음을 확인합니다: 11월 이동 시 누적 9.00km 유지, 11월 5km 추가 시 14.00km, 10월 화면에 11월 기록 미포함, 삭제 시 누적 감소, 주·월·년·전체 집계, 레벨 경계 50/250/1,000/2,500km와 색상 적용, 기존 localStorage를 조회만으로 다시 쓰지 않음·기존 기록 원형 유지·손상 시 덮어쓰기 차단, 새로고침 후 기록·통계 유지.

OCR 테스트(21개)는 `fixtures/`의 실제 Tesseract.js 출력(NRC 형식의 라이트·다크 모의 캡처, 실제 NRC 상세 목록 캡처 `nrc-list.tsv`)으로 라벨·값 짝짓기, 재판독 보정, 날짜 형식, 마일 변환, 범위 검사를 확인하고, 앱 이벤트로 자동 기입·저장 전 미저장·늦은 결과 무시·실패 안내를 확인합니다. 실제 Chromium에서 모의 캡처 두 장과 실제 NRC 상세 목록 캡처(2026-10-09 러닝)를 앱에 올려 모든 값이 맞게 채워지는 것을 확인했습니다(실제 캡처: 2.71km, 28:24, 122kcal, 163spm, +8m, 149/163bpm). 실제 iPhone Safari에서의 OCR 속도는 별도로 확인이 필요합니다.

실제 브라우저(Chromium, 390px/320px): 기간·모드 전환, 11월 누적 9.00km 유지, 11월 기록 추가→새로고침→삭제 후 localStorage 원상 복구, 긴 누적 거리(퍼플) 배치를 확인했습니다. 실제 iPhone Safari 하드웨어/키보드 검증은 별도로 필요합니다.
